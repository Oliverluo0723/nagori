# 即時彈奏 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 不丟歌，打開 Nagori 按電腦鍵盤就有聲音，選好的拼塊即時畫出彈的東西。

**Architecture:** 按鍵事件由一個純函式翻成現有的 `Readings`，look 和 `renderFrame` 完全不知道資料是彈出來的。預覽多一個「即時來源」，有它的時候時間和讀數都向它要，不讀 `<audio>`。`App.tsx` 在沒有歌時接鍵盤、發聲、只列出可用的 look。

**Tech Stack:** TypeScript、React 19、p5（既有的 `createGraphics`）、Web Audio、vitest（node 環境）、biome。

**Spec:** `docs/superpowers/specs/2026-11-21-live-play-design.md`

## Global Constraints

- **不 commit。** 使用者說 commit 才 commit；每個 task 結束只跑檢查
- 每個 task 結束 `pnpm test`、`pnpm typecheck`、`pnpm lint` 全綠
- 不要啟動 `pnpm dev` 或任何本機伺服器（會被擋）；需要看畫面時請使用者開
- look 不讀 `Date`、不用 `Math.random`；`src/live/readings.ts` 也一樣，時間一律由參數給
- 固定 120 BPM、4/4；調固定 C 大調；頻譜不做（`spectrum` 留 `undefined`）
- 鍵位用 `KeyboardEvent.code`（實體位置），不用 `key`：注音輸入法開著時 `key` 是 `Process`
- 原本丟歌的流程不能變：有歌時鍵盤不彈奏、38 個 look 都在
- 註解與介面文字用繁體中文，沿用現有檔案的寫法

## Review Focus

1. 注音輸入法開著時按 `A`：照樣出聲、畫面有反應（Task 1 的鍵位表用 `code`；Task 5 的測試）
2. 按住不放產生的重複 keydown：只算一顆音，不會疊出一串（Task 5）
3. `Cmd+C`、`Ctrl+R` 這類組合鍵：不觸發 hat 或任何音，瀏覽器原本的行為照常（Task 5）
4. 按著鍵時切到別的視窗：音不會卡住一直響（Task 5 的 blur 處理）
5. 還沒按任何鍵、或只按過鼓沒按過音：六個 look 都畫得出來，不丟例外（Task 2 的 smoke test）

// keys.ts
export type LiveKey = { kind: 'note'; midi: number } | { kind: 'drum'; drum: DrumKind };
/** KeyboardEvent.code → 鍵。 */
export const KEY_MAP: Readonly<Record<string, LiveKey>>;
/** 顯示用的一行提示 */
export const KEY_HINT = 'A S D F G H J K 彈音　W E T Y U 黑鍵　Z X C 鼓';

// readings.ts
export type LiveEvent =
  | { type: 'on'; midi: number; time: number }
  | { type: 'off'; midi: number; time: number }
  | { type: 'drum'; drum: DrumKind; time: number };
export const LIVE_BPM = 120;
export const LIVE_NOTE_RANGE: [number, number] = [58, 74];
export function liveReadings(events: readonly LiveEvent[], now: number): Readings;
export interface LiveSession {
  noteOn(midi: number, time: number): void;
  noteOff(midi: number, time: number): void;
  drum(drum: DrumKind, time: number): void;
  /** 放開所有按住的音 */
  releaseAll(time: number): void;
  /** 沒有新事件、也沒有按住的音時，回傳同一個物件（look 的快取以物件識別） */
  readings(now: number): Readings;
}
export function createLiveSession(): LiveSession;

// analysis/types.ts，Readings 內
/** 鋼琴捲的列範圍；有給就用，沒給由 notes 算 */
noteRange?: [number, number];
```

`KEY_MAP` 的值：`KeyA`=60、`KeyW`=61、`KeyS`=62、`KeyE`=63、`KeyD`=64、`KeyF`=65、`KeyT`=66、`KeyG`=67、`KeyY`=68、`KeyH`=69、`KeyU`=70、`KeyJ`=71、`KeyK`=72；`KeyZ` kick、`KeyX` snare、`KeyC` hat。

`liveReadings` 的規則：

| 欄位 | 值 |
|---|---|
| `duration` | `Math.max(60, now)` |
| `tempo` | `tempoMapFromBpm(LIVE_BPM)` |
| `notes` | 每個 `on` 一顆，配到同 midi 的下一個 `off`；沒有 `off` 的長度是 `now − time`（最少 0.02）；`velocity` 0.8；依 `time` 排序 |
| `drums` | 每個 `drum` 一個 hit，`velocity` 1 |
| `bass` | 掃過 on/off，每段「按住的音不變」的時間裡取最低的那顆，一段一個 `BassNote`，`bends: []`；沒有按住的音就沒有 |
| `chords` | 同樣分段；按住的 pitch class 集合剛好等於 `QUALITIES`（`src/analysis/audio/chords.ts`）某個根音的模板時出一個 `ChordEvent`，`name` 用 `chordName`。多個候選時取根音等於最低音的；都不是就取根音數字最小的 |
| `key` | `{ tonic: 0, mode: 'major', name: 'C major' }` |
| `noteRange` | `LIVE_NOTE_RANGE` |
| `roles` | `[]` |
| `source` | tempo、drums、chords、bass、key、notes 全部 `'midi'` |

`on` 時該 midi 已經按著就忽略；`off` 時沒按著也忽略。bass 與和弦分段時，長度為 0 的段落丟掉（同一刻按下三顆音只出一個和弦）。`createLiveSession` 最多留 4000 個事件，超過丟最舊的；沒有按住的音時它不看 `now`，直接回上一次的物件。

注意 `src/analysis/audio/chords.ts` 最上面 import 了 `essentia`；node 測試載入它如果有問題，把 `QUALITIES` 和 `chordName` 搬到 `src/looks/music.ts` 再從原處 re-export。

// input.ts：鍵盤事件 → 要做的事。純函式，App 只負責照做
export interface KeyInput {
  code: string;
  repeat: boolean;
  metaKey: boolean;
  ctrlKey: boolean;
  altKey: boolean;
  /** 事件目標的 tagName */
  target: string;
}
/** 回傳要處理的鍵；不該處理（重複、組合鍵、在輸入框裡、不在鍵位表）回 null */
export function liveKeyFor(e: KeyInput): LiveKey | null;
```

`App.tsx` 的行為：

- `const liveMode = state.status === 'empty' || state.status === 'error'`
- `root` 的初始值改成 `liveLayout(` 內建版型 `stack` `)`，`selectedId` 仍是 `'c1'`
- 即時模式下按版型鈕：`setRoot(liveLayout(p.build()))`
- 進入即時模式：建立一個 session 和一個 synth，`preview.setLive({ now, readings })`；離開（歌分析好了）：`setLive(null)`、`synth.allOff()`。元件卸載時 `synth.close()`
- 時間：第一個被處理的 keydown 的 `timeStamp` 是零點；`now()` 是 `(performance.now() − 零點) / 1000`，還沒按過鍵時是 0；事件時間同樣用 `e.timeStamp` 換算
- keydown：`liveKeyFor` 有結果就 `preventDefault()`，音 → `session.noteOn` + `synth.noteOn`，鼓 → `session.drum` + `synth.drum`
- keyup：只看 `code` 在 `KEY_MAP` 且是音 → `noteOff`（不管修飾鍵，放開一定要收）
- `window` 的 `blur`：`session.releaseAll(now)` + `synth.allOff()`
- 右欄 look 清單和 ↑↓：即時模式只有 `isLiveLook` 的那些，分組標題照舊，數量跟著變
- 播放列：即時模式下整塊換成一行 `KEY_HINT`（class `live-hint`）；左欄 `hint-keys` 只留 ↑↓ 換 look
- 有歌時以上全部不生效
